## What it is

Agents repair small printed-circuit-board designs with injected faults. Each design has two
files: a schematic of record (`design.json`) and a KiCad 7 layout (`board.kicad_pcb`). The agent
works with a shell and a domain CLI (`pcbtool`: inspect, simulate, DRC/ERC, edit, route). A
**deterministic verifier** grades the two deliverable files against a hidden golden. It runs
structural gates, KiCad DRC, an ERC, SPICE assertions (ngspice), value bounds, datasheet design
rules and board-geometry rules. The reward is binary: 1 only if everything passes. No LLM judge
is involved.

## Why it matters to a lab

- **The reward equals correctness, and we have evidence for it.**
  - All 1464 shipped tasks score 0.0 when faulted and 1.0 when the oracle repair is applied
    (§5).
  - The red team ran 3500 scripted attack applications in its final runs plus 148 agent/hand
    attempts, with **0 successful reward hacks** (§9).
  - Five past verifier gaps that the red team found are all fixed (§9).
- **It trains a transferable behaviour: verifying before you submit.** On the hard tiers, every
  failure of a mid-tier model was a requirement that the local tool does not check but the task
  states (§3). A careful small model beat a hasty larger one (§1).
- **Fresh, uncontaminated tasks on demand.**
  - Tasks are 100 % synthetic and procedurally generated from keyed seeds, with opaque ids.
  - A refresh engine produces new gated tasks, deduplicated against the shipped set.

## Task tiers (§8)

| tier | tasks (train / holdout) | what's in a task |
|---|---|---|
| normal | 819 (655 / 164) | 10 circuit families, 1–3 faults, 19 fault types |
| hard | 452 (362 / 90) | mostly 20–27-part multi-rail composite boards, 3–6 faults, ≥ 2 latent (invisible to every `pcbtool` check, deducible from datasheets / intent / stated rules) |
| hard_layout | 193 (154 / 39) | hard + board-geometry rules (Kelvin sense, switching-loop area, crystal path, analog/switching separation, decoupling copper path), mostly no-autoroute |

**Honest framing.** The normal tier is saturated. The hard tiers put mid-tier agents into the
learnable band. The strongest model we tested stays at about 95 %. Difficulty here comes from
diligence (checking every stated rule), not from frontier capability. We do **not** claim a
frontier-hard benchmark. `reports/INTERPRETATION.md` explains why and lists what we would build
next for that.

## Integration

- **Python API and gym-like env:** `PcbRepairEnv` (reset / step / reward), plus
  `run_agent(task, call_model)` for any model.
- **JSONL:** export public task files in HF-datasets style; batch-score predictions in parallel,
  isolated subprocesses.
- **Inspect (UK AISI):** a `Task` with sandboxed bash + `pcbtool` and a host-side verifier scorer.
- **Runs locally:** Ubuntu 24.04, KiCad 7.0.11, ngspice, Python 3. Verification median is 0.54 s per
  task (G3 measurement, `scorecard/STATUS.md`), and the README quickstart takes minutes (fresh-agent onboarding was verified twice,
  `scorecard/STATUS.md` G8).
